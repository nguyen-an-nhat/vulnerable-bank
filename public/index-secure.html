Trình diễn cách sửa các lỗ hổng SQL Injection và XSS

✅ Phiên bản này đã được vá lỗi chống lại các tấn công SQL Injection và XSS

🔧 Phần A: Sửa SQL Injection

✅ Giải Pháp: Sử Dụng Truy Vấn Được Tham Số Hóa

Thay vì nối chuỗi, hãy sử dụng chỗ dùng tham số giúp tách đầu vào người dùng khỏi mã SQL.

Giải Pháp Giải Thích:

MÃ LỖ HỔNG:

// ❌ LỖ HỔNG - Nối chuỗi const query = `SELECT * FROM users WHERE username = '${username}' AND password = '${password}'`; db.get(query, (err, row) => { ... });

MÃ AN TOÀN:

// ✅ AN TOÀN - Truy vấn được tham số hóa const query = `SELECT * FROM users WHERE username = ? AND password = ?`; db.get(query, [username, password], (err, row) => { ... });

Tại Sao Nó Hoạt Động:

  • Tách Mã Và Dữ Liệu: Chỗ dùng ? được thay thế bằng trình điều khiển cơ sở dữ liệu, không phải bằng nối chuỗi
  • Được Coi Là Dữ Liệu: Đầu vào người dùng luôn được coi là giá trị dữ liệu, không bao giờ là mã SQL có thể thực thi
  • SQL Injection Không Thể: Ngay cả khi bạn nhập ' OR '1'='1, nó được coi là chuỗi ký tự theo nghĩa đen để tìm kiếm

Thử Tấn Công Trên Phiên Bản An Toàn:

📚 Ghi Chú Bảo Mật Bổ Sung:

  • Tất Cả Truy Vấn Cơ Sở Dữ Liệu: Sử dụng truy vấn được tham số hóa cho mọi hoạt động cơ sở dữ liệu (SELECT, INSERT, UPDATE, DELETE)
  • ORMs: Hầu hết các ORMs (Sequelize, TypeORM) sử dụng các truy vấn được tham số hóa theo mặc định
  • Các Tuyên Bố Được Chuẩn Bị: Hoạt động tương tự trên tất cả các cơ sở dữ liệu chính (MySQL, PostgreSQL, SQL Server)
  • Đào Tạo Nhà Phát Triển: Đây là phòng ngừa quan trọng nhất chống lại SQL injection

🔧 Phần B: Sửa Cross-Site Scripting (XSS)

✅ Giải Pháp: Vệ Sinh HTML + Cookie HttpOnly

Hai cách tiếp cận bổ sung để ngăn chặn các tấn công XSS.

Giải Pháp 1: Vệ Sinh HTML

MÃ LỖ HỔNG:

// ❌ LỖ HỔNG - HTML thô từ đầu vào người dùng const notification = ` <div>Tin Nhắn: ${message}</div> `; res.json({ html: notification });

MÃ AN TOÀN:

// ✅ AN TOÀN - Thoát các ký tự HTML đặc biệt function escapeHtml(text) { const map = { '&': '&', '<': '<', // < trở thành < '>': '>', // > trở thành > '"': '"', "'": ''' }; return text.replace(/[<>"']/g, m => map[m]); } const escapedMessage = escapeHtml(message); const notification = `<div>Tin Nhắn: ${escapedMessage}</div>`;

Vệ Sinh HTML Làm Gì:

❌ Mà Không Vệ Sinh
Đầu Vào: <img src=x onerror="alert('XSS')"> HTML Đầu Ra: <img src=x onerror="alert('XSS')"> Kết Quả: Trình duyệt hiển thị thẻ và thực thi JavaScript!
✅ Với Vệ Sinh
Đầu Vào: <img src=x onerror="alert('XSS')"> HTML Đầu Ra: &lt;img src=x onerror="alert('XSS')"&gt; Kết Quả: Trình duyệt hiển thị nó dưới dạng văn bản, không phải HTML!

Giải Pháp 2: Cookie HttpOnly

COOKIE LỖ HỔNG (có thể bị đánh cắp bởi XSS):

// ❌ LỖ HỔNG - JavaScript có thể truy cập cookie này res.cookie('session_user', username, { httpOnly: false // JavaScript trình duyệt có thể đọc điều này! }); // Kẻ tấn công có thể đánh cắp nó bằng: document.cookie

COOKIE AN TOÀN (được bảo vệ khỏi XSS):

// ✅ AN TOÀN - JavaScript không thể truy cập cookie này res.cookie('session_user', username, { httpOnly: true, // Chỉ được gửi qua HTTP, không thể truy cập thông qua JavaScript secure: true, // Chỉ được gửi qua HTTPS sameSite: 'strict' // Không thể được gửi trong các yêu cầu qua site }); // Ngay cả khi kẻ tấn công chèn JavaScript, nó cũng không thể đọc document.cookie!

Thử Tấn Công Trên Phiên Bản An Toàn:

Đặt cookie phiên an toàn trước:

3 Loại XSS & Cách Sửa

1. Reflected XSS

Lỗ Hổng: Phản ánh đầu vào người dùng trực tiếp vào HTML

Sửa: Thoát HTML tất cả dữ liệu trước khi hiển thị

2. Stored XSS (Nguy Hiểm Nhất!)

Lỗ Hổng: Lưu payload vào database, tấn công tất cả người xem

Sửa: Thoát HTML cả khi lưu lẫn khi lấy từ database

3. DOM-based XSS

Lỗ Hổng: JavaScript sử dụng innerHTML với dữ liệu chưa xử lý

Sửa: Sử dụng textContent thay vì innerHTML

📊 So Sánh Theo Cạnh

Bảo Vệ SQL Injection

❌ Cách Tiếp Cận Có Lỗ Hổng
Nối Chuỗi: query = "SELECT * FROM users WHERE username = '" + username + "'" Tấn Công: username = "' OR '1'='1" Truy Vấn Kết Quả: SELECT * FROM users WHERE username = '' OR '1'='1' Kết Quả: Trả về tất cả users!
✅ Cách Tiếp Cận An Toàn
Truy Vấn Được Tham Số Hóa: query = "SELECT * FROM users WHERE username = ?" db.get(query, [username]) Tấn Công (cùng đầu vào): username = "' OR '1'='1" Hành Vi: Tìm kiếm kết quả chính xác của chuỗi "' OR '1'='1" Kết Quả: Không tìm thấy users (như dự định)

Bảo Vệ XSS

❌ Cách Tiếp Cận Có Lỗ Hổng
Đầu Ra Trực Tiếp: output = <div>${userInput}</div> Tấn Công: userInput = <img src=x onerror="alert('XSS')"> HTML Được Hiển Thị: <div><img src=x onerror="alert('XSS')"></div> Kết Quả: JavaScript thực thi!
✅ Cách Tiếp Cận An Toàn
Đầu Ra Được Thoát HTML: output = <div>${escapeHtml(userInput)}</div> Tấn Công (cùng đầu vào): userInput = <img src=x onerror="alert('XSS')"> HTML Được Hiển Thị: &lt;img src=x onerror="alert('XSS')"&gt; Kết Quả: Hiển thị dưới dạng văn bản, không được thực thi!

🛡️ Danh Sách Kiểm Tra Bảo Mật Hoàn Chỉnh

  • ✓ Tất Cả Truy Vấn Cơ Sở Dữ Liệu: Sử dụng các truy vấn được tham số hóa (các tuyên bố được chuẩn bị)
  • ✓ Đầu Ra Đầu Vào Người Dùng: Thoát HTML tất cả dữ liệu được điều khiển bởi người dùng trước khi hiển thị
  • ✓ Cookie: Đặt các cờ HttpOnly, Secure và SameSite
  • ✓ Xác Thực Đầu Vào: Xác thực và vệ sinh tất cả đầu vào trên máy chủ
  • ✓ Chính Sách Bảo Mật Nội Dung: Đặt tiêu đề CSP để hạn chế các nguồn tập lệnh
  • ✓ Chỉ HTTPS: Luôn sử dụng HTTPS trong sản xuất
  • ✓ Tiêu Đề Bảo Mật: Triển khai X-XSS-Protection, X-Content-Type-Options
  • ✓ Cập Nhật Thường Xuyên: Giữ cho các phụ thuộc và khung được cập nhật
